# Project config as an override layer

> **Status:** accepted — supersedes [ADR-0007](./0007-project-level-config.md).

A project can commit `.pi/subagents-lite.json` so every team member gets the same model and concurrency defaults. The project file is an override layer over the global file, not a replacement: it may contain only model and concurrency keys, each key it sets wins over the global value, and an absent key inherits from the global file (or built-in defaults). The effective config is computed by walking session overrides → project file → global file → built-in defaults, and the merged result is never written back to either file: global writes update only the global layer, project writes only the project layer. Clearing a project value deletes the key, so the value falls through to global; clearing at global falls through to the built-in default; clearing at session falls through to the config files. Unknown keys in a hand-edited project file are ignored with a warning; a malformed project file is ignored and the project level is not offered; an empty file (`{}`) is inert. The project layer loads and the project target is offered only in trusted projects, same as `.pi/agents`.

## Considered options

- **One file wins, wholly (ADR-0007, never released).** A valid project file replaces the global file entirely. Simple and self-contained, but a committed project file hijacks personal settings: later global edits stop applying, and removing a setting means writing a baked default — inheritance is impossible. Rejected once inheritance became a requirement.
- **v1 per-field merge with save-time diffing and `null` tombstones (pre-ADR-0007, in git history).** Project wins per field, saves re-derive the diff from the merged config, deletions are tombstones with per-key null semantics. Achieves inherit and remove, but at the cost of load-time file-specific null meaning, save-time diff re-derivation, and surprising interactions when the global file changes under a project.
- **Override layer (chosen).** Inheritance is absence: no tombstones, no diffing, no null semantics. Removal is key deletion, which is exactly "inherit the lower layer". Each file stores only its own layer, so provenance is derived from layer membership (the layer containing a key is its source), hand-edits stay predictable, and reload is a plain re-read of both files. The cost: the project file is not self-contained — its effective values depend on the global file — and the write model changes from "save the full effective config" to "persist the touched layer".
