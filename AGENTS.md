# Dev

- Use `vp`; before committing run `vp check` and `vp test run`. Node/toolchain versions are pinned in `.node-version` and package files. Install with `vp install`; regenerate, never hand-edit, lockfiles.
- Type tests with real `src/pi` types and typed fixtures; prefer `unknown` + narrowing, and use documented `any` only for reproduced limitations. Use `interface` for object shapes, `type` otherwise. Put pi-tui private casts in `test/pi-boundaries.ts`.
- Update `CHANGELOG.md` Unreleased for user-facing changes. Keep Unreleased empty at release. 
- Pi source: `../pi`.

## Lessons

- **Test reality:** Exercise public seams and verify producer output (raw SSE, loopback capture, `tool_execution_end.result`). Pin dependency schemas against real schemas (`vi.importActual`); mocks can hide production fallbacks. Fixtures must reflect real inputs and objects. Use raw malformed file text, preserve base fixture values with `?? base`, and mock private classes at their real call boundary.
- **Assert behavior:** Pin exact order/arrays when layout matters; trim padded `Text.render()` rows. Capture earlier state before mutation, anchor positive shape before negative assertions, and assert every claimed read-back line. Check transition criteria and existing unit pins before changing acceptance expectations.
- **Avoid vacuity:** A bare `Promise.race` value wins after one microtask; use a task-bounded pending arm. For `clockedLoopback`, await `requestAt` before clock steps; `vi.waitFor` advances fake time. Install endpoint config before `session_start` to avoid the real user config. Distinguish scenarios with differing inputs and mutate the guard; test both branches, multiple bound runs for per-run claims, and exact arrays at the sequence-ending milestone. Start replacement sessions before advancing clocks when queued work must not land there.
- **Mocks and mutation checks:** `vi.fn(impl)` may need a wider generic for replacement returns; `ReturnType<typeof vi.fn>` is only its constraint. Node builtin ESM namespaces reject `vi.spyOn`; use partial import mocks. Report mutation reds from `FAIL` lines; scoped runs prove only their scope. Verify file lists and arithmetic.
- **Runtime boundaries:** Mirror all callbacks on reused run paths and scan only messages added in the current run. `steer` queues only while the parent runs (`ctx.isIdle()`); extension re-imports across cwd changes require child capabilities in `Symbol.for`-shared `AsyncLocalStorage`. `dispose()` is not `session_shutdown`; child binding fires parent `session_start`; one-shot gates hide recurring events.
- Validate the assembled route at every ingress/normalization layer; preserve omitted, invalid or inadmissible values for the owning boundary and enforce config constraints at every entry point. Put side effects on authoritative transitions, not correlated signals. Render from contract answer fields; keep detail switches with workflow authors. Keep model-hidden data unreachable and redacted: Pi persists tool `details` and `pi-messages` posts transcripts unchanged. Match model-facing text to actual schemas/channels. After failed reads, require a `running` read before expecting streams to reopen. For new settings, trace type/default/resolution/setter/sync/keys/internal defaults and test survival of clear-all paths.
- **UI and errors:** SettingsList is for toggles, submenus, separators and static rows; never call `ctx.ui.input/select/custom` inside it. Submenu changes need `onRebuild`; chain with `createDelegatingComponent`, centralize separator skipping, initialize navigation like the library, and provide remove paths for overrides. Event-listener `abort()`/`steer()` promises need `void promise.catch(() => {})`, including mocks. Tool rendering follows Pi lifecycle events (AgentManager `onStart` precedes `tool_execution_start`); use `toolCallId` to retrieve data absent from `context.state`.
